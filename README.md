# JKBMS-Android

[简体中文](README.md) · [English](README_EN.md)

JKBMS-Android 是一个用来连接极空（JK）BMS 的第三方 Android 应用。手机通过蓝牙直接读取电池数据，可以查看电芯电压、电流、功率、温度、剩余电量和告警，也可以结合 GPS 速度估算行驶能耗与剩余里程。应用不需要注册账号，读取的数据和设置都留在本地。

目前版本是 **1.3.1（19）**，支持 Android 8.1 及以上系统。最近的更新修复了分屏后导航消失、回到前台后蓝牙数据不再更新的问题，并加入自动录制、速度曲线和双图显示。首页卡片和仪表的单位也统一放到了数值旁。完整变化见[更新日志](CHANGELOG.md)。

## 安装与连接

安装包可以在 [GitHub Releases](https://github.com/mazemingw/JKBMS-Android/releases) 下载。

**1.3.0 更换了发布签名。** 已安装 1.2.8 正式版或旧调试版的用户，需要先卸载旧版再安装。卸载会清除应用中的设置和统计，请先保留需要的信息。后续继续使用这把新密钥签名的版本可以直接覆盖升级。

打开应用后，进入底部的“蓝牙”页面，允许附近设备权限，扫描并选择自己的保护板，再输入设备密码连接。旧版 Android 的蓝牙扫描还需要定位权限；要使用 GPS 测速和能效估算，也需要允许精确定位。设备密码验证通过后，首页就会开始更新。

应用会记住上次成功连接的设备和密码，下次打开时自动尝试连接。遇到数据不再更新，应用会清除失效的实时读数并重连：正常采集时，连续约 3 秒没有收到有效电池数据就会触发恢复；连接、发现服务或认证过程卡住，则最多等待 15 秒。单独收到一些蓝牙分包，或者收到校验失败的数据，都不会让旧读数一直留在界面上。

## 首页怎么看

首页放的是日常最常看的信息：运行时间、蓝牙状态、GPS 速度、电流、功率、电量和总电压，往下还有告警、板上指标和各节电芯电压。数值与单位放在同一行，窄屏下会自动缩小文字，方便一眼读完。

点击速度卡片可以开关 GPS。设置里可以选择顶部是否使用大仪表、切换仪表的数据源和量程，也可以调整主题、字体，隐藏速度卡片或能效面板。

能效卡片默认显示行程数据。如果上次有记录，重新打开应用时就能看到上次的里程、耗电和能效，不用等重新连上保护板；确认开始新一程后，卡片才会换成本次数据。点击右上角标签，可以在 TRIP A、TOTAL 和近一分钟曲线之间循环查看。TRIP A 是单次行程，TOTAL 是跨多次启动保存的累计统计。设置里的“清除 TOTAL”会先弹出确认框，清除总计时会保留当前行程。

“分屏信息”适合把应用放在系统小窗或分屏中使用。开启后，只有系统确实处于小窗或分屏、且当前在信息页时，才会收起底部导航。普通手机全屏打开时会照常显示导航。精简界面上也留了“恢复导航”按钮，按系统返回键同样可以退出，不需要清除应用数据。

首页的 MOCK 按钮可以生成一段模拟行车数据，里面有加速、巡航、回收、停车和再次起步，方便没有连接保护板时试用界面。开启 GPS 后，模拟模式也会提供模拟速度。模拟数据不会计入 TOTAL，也不会覆盖保存的真实行程。设置里可以隐藏这个按钮。

## 曲线会自动录制

收到电池数据后，应用就会开始录制电压、电流、功率和电量，不需要先进入图表页。打开 GPS 后还会记录有效速度；即使保护板暂时断开，GPS 速度也可以单独继续记录。定位无效或蓝牙断线的地方会留出缺口，方便分辨哪些时段缺少数据。

图表页默认显示两张 ECharts，分别是电压和速度。点击每张图的标题，可以独立选择电压、电流、功率、电量或速度，也可以切回单图显示。这些选择会保存下来。手机竖屏时两图上下排列，窗口足够宽时会并排显示。

实时模式看最近 60 秒；点击“回读全程”，可以查看进入回读时已经录下的数据，同时后台仍会继续录制。“暂停录制”和“继续录制”也会保留已有样本。当前最多保留 7200 个样本，曲线保存在本次应用进程内，结束进程后不会留作历史记录。

图表使用随安装包附带的 ECharts，不需要联网加载。首页的大仪表由 Compose Canvas 绘制。

## 能效是怎么估算的

能效需要同时拿到可靠的 GPS 速度和电池电流。应用对速度积分得到距离，对电流积分得到消耗与回收的安时数，再用里程除以净耗电量。这里采用 JK 数据的电流方向：负数表示放电，正数表示充电或行驶中的能量回收。

```text
净耗电 Ah = 累计放电 Ah − 累计回收 Ah
能效 km/Ah = 有效里程 km ÷ 净耗电 Ah
预计剩余里程 km = 剩余容量 Ah × 能效 km/Ah
```

界面会把能效写成 `1Ah 3.0km` 这样的形式，意思是每消耗 1Ah，大约能行驶 3 公里。回收的电量会从净耗电里扣除。刚起步时数据很少，结果容易波动，所以行程至少积累约 0.1 公里和 0.01Ah 净耗电后，才会显示单次能效。预计里程优先使用本次行程的结果，样本不够时参考 TOTAL 的平均值。

速度达到 3km/h 并持续约 3 秒，应用会确认起步。速度低于 1km/h 时，耗电积分立即暂停；停留 15 秒进入临停状态，短暂停车后继续行驶仍算同一程。静止约 3 分钟后，这一程结束，数据保留到下次确认起步。

定位恢复和蓝牙重连时，应用会重新建立采样基线，缺失的时段不会补算进去。GPS 恢复后需要连续两个新鲜定位点，过旧、误差过大或速度异常的定位会被忽略。这样做会少记一部分信号不好的路段，但能避免把断线期间的旧电流或旧速度算成新的能耗。

TRIP A、运行统计、TOTAL 和用于展示的剩余容量会定期保存到本地。重启后恢复的是统计结果，积分时钟会重新开始。目前只保留最近一次行程和累计汇总，还没有可以逐条查询的历史行程数据库。

如果希望切到其他应用或锁屏后继续采集，可以在设置中开启“后台能耗采集”。应用会通过前台服务、持续通知和唤醒锁保持蓝牙与 GPS 采集；部分手机还需要在系统设置里允许后台运行。关闭这项设置时，退到后台会暂停能耗统计。系统强制停止应用后，持续采集无法保证，再次打开时会恢复保存的数据并检查连接。

这些结果适合观察自己的用电习惯和续航变化。路况、温度、风阻和骑行方式都会影响实际续航，电池与车辆状态请结合保护板、仪表和实际测量判断。本项目与极空官方没有关联，目前的协议解析主要针对已测试的 300 字节 JK 状态帧，其他硬件或固件可能需要适配。

## 从源码构建

项目使用 Kotlin、Jetpack Compose 和 Android Gradle Plugin，编译 SDK 为 36。请使用 **JDK 17** 和仓库里的 Gradle Wrapper；当前 Gradle/Kotlin 组合无法以 JDK 25 启动。用 Android Studio 打开项目后，确认本地 Android SDK 路径正确，也可以直接运行：

```powershell
$env:JAVA_HOME = "C:\Program Files\Java\jdk-17"
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

macOS 或 Linux 下使用 `./gradlew`。Debug 包输出到 `app/build/outputs/apk/debug/app-debug.apk`。连接手机或启动模拟器后，运行 `connectedDebugAndroidTest` 可以检查导航恢复、历史能效、自动录制和双图设置等场景。

正式构建需要在本地或 CI 中设置 `JKBMS_KEYSTORE_PATH`、`JKBMS_KEYSTORE_PASSWORD`、`JKBMS_KEY_ALIAS` 和 `JKBMS_KEY_PASSWORD` 四个环境变量，然后运行 `assembleRelease`。密钥和密码无需写进项目。未提供签名配置时，Gradle 生成的是未签名 Release 包；用于下载的正式签名包同时放在 `app/release/app-release.apk` 和 GitHub Release 中。

要修改代码，可以先从 [MainActivity.kt](app/src/main/java/com/yiming/jkbms/MainActivity.kt) 看蓝牙、GPS 和页面的衔接，再看 [EnergyTracker.kt](app/src/main/java/com/yiming/jkbms/model/EnergyTracker.kt) 中的行程与积分逻辑。[BleRecoveryPolicy.kt](app/src/main/java/com/yiming/jkbms/model/BleRecoveryPolicy.kt) 负责判断连接是否超时，[EnergyHistoryStore.kt](app/src/main/java/com/yiming/jkbms/model/EnergyHistoryStore.kt) 负责保存上次能效。界面在 `ui/screens`，ECharts 的桥接组件在 `ui/components/EChartsLine.kt`，网页和脚本在 `app/src/main/assets/echarts`。

遇到问题欢迎[提交 Issue](https://github.com/mazemingw/JKBMS-Android/issues)。尽量附上手机与系统版本、保护板型号，以及出现问题前后的操作，这样更容易定位。
