# JKBMS-Android

[简体中文](README.md) | [English](README_EN.md)

JKBMS-Android 是一个使用 Kotlin 与 Jetpack Compose 编写的极空（JK）BMS 第三方 Android 客户端。手机可以通过 BLE 直接连接保护板，读取并展示电芯、电流、电压、功率、温度、SOC、告警等数据，不依赖厂商云服务。

当前版本：`1.2.8 (17)`，最低支持 Android 8.1（API 27）。

版本变化见 [CHANGELOG.md](CHANGELOG.md)，英文版见 [CHANGELOG_EN.md](CHANGELOG_EN.md)。

> 本项目不是极空官方应用。不同硬件或固件版本的协议可能存在差异，涉及车辆与电池安全的判断应以 BMS、仪表和实际测量结果为准。

## 主要功能

- 直接扫描并连接 JK BMS，校验设备密码后读取状态数据。
- 首页集中展示运行时间、BLE 状态、GPS 速度、功率大仪表、电流、SOC、电压及板上指标。
- 功率大仪表继续使用 Compose Canvas，支持电压、电流、功率切换、正负向显示及烟雾动画。
- 本地 ECharts 实时图表，支持电压、电流、功率、SOC 录制、最近 60 秒显示和全程回读。
- GPS 与 BMS 联合计算行驶能效、回收电量及预计剩余里程。
- MOCK 行车模式覆盖加速、巡航、动能回收、城区变速和停车场景。
- 深色、浅色、跟随系统主题，可选应用字体、速度卡片、分屏精简模式和仪表量程。
- BLE 数据超时自动重连；MOCK 开启时真实 BMS 帧只缓存，不与模拟数据争抢界面。
- 可选后台能耗采集，以前台服务、持续通知和唤醒锁保持 BLE、GPS 与积分运行。
- 能效卡片支持“曲线 / TRIP A / TOTAL”三态，点击右上角单按钮循环切换；TOTAL 里程与平均能效跨启动保存。
- 底部导航采用悬浮胶囊式半透明磨砂外观；设置中可隐藏首页 MOCK 测试按钮。

## 行驶能效

能效模块同时使用 GPS 速度和 BMS 电流，并以单调时钟进行梯形积分。JK BMS 在本项目中的电流方向约定为：

- 负电流：放电；
- 正电流：充电或行驶中的动能回收。

计算口径如下：

```text
放电量 Ah = ∫ max(-电流, 0) dt
回收量 Ah = ∫ max( 电流, 0) dt
净耗电 Ah = 放电量 - 回收量
行驶距离 km = ∫ GPS速度 dt
能效 km/Ah = 行驶距离 ÷ 净耗电
预计里程 km = BMS剩余容量Ah × 有效能效km/Ah
```

界面使用更适合两轮车阅读的 `1Ah Xkm` 表达，例如 `1Ah 3.0km` 表示每消耗 1Ah 约可行驶 3km。动能回收会降低净耗电，因此会提高最终的 `km/Ah`。

### 折线与饼图的时间范围

| 视图 | 数据范围 | 含义 |
| --- | --- | --- |
| 能效折线 | 最近 60 秒 | 约 2Hz 更新的滚动能效；旧点从左侧退出，并标记当前窗口 MAX/MIN |
| 放电/回收饼图 | 整个本次行程 | 橙色为累计放电，绿色为累计回收；下方显示回收占总吞吐量的百分比 |
| TRIP A | 当前行程 | 显示本次里程、本次净耗电、单次能效、回收量与预计里程 |
| TOTAL | 持久累计 | 显示总里程、总净耗电、长期平均能效与累计回收，关闭或重启应用后仍保留 |

饼图的回收比例为：

```text
回收比例 = 回收Ah ÷（放电Ah + 回收Ah）
```

它不是净耗电占比，也不受折线图 60 秒窗口限制。

### 起步、停车与暂停规则

- GPS 速度达到 `3km/h` 并持续 3 秒后确认起步。
- GPS 速度低于 `1km/h` 时，能量积分、能耗累计、折线和饼图立即冻结。
- 连续低速 15 秒后进入临停状态，但短暂停车不会拆分行程。
- 静止达到 3 分钟后结束本次行程；已完成的数据保留到下一次确认起步。
- 再次起步时从新的 BMS 帧恢复积分，不会跨越停车时段补算耗电。
- GPS 信号失效或停止采集时同样切断积分连续性；未开启“后台能耗采集”时，应用进入后台也会暂停。

因此，停车期间的灯光、控制器待机等耗电当前不会计入行驶能效。这一口径用于回答“车辆移动一段距离需要多少 Ah”，而不是整车静态用电审计。

### GPS 数据质量

能效计算只接收带速度的定位结果。当前容差为定位精度不超过约 `60m`、速度误差不超过约 `5m/s`、定位结果到达时不旧于 `2.5s`，并过滤超过 `200km/h` 的异常速度。GPS 失效后，恢复的第一个合格定位点只用于重新建立时间基线，连续收到第二个新鲜定位点后才恢复能耗积分，因此不会把停车或失联时长补算进一帧数据。GPS 开关打开后，即使隐藏首页速度卡片，能效采集仍可继续。

### 后台能耗采集

“设置 → 后台能耗采集”默认关闭。开启后会自动开启 GPS，并启动带持续通知的前台服务；应用退到后台时不再主动停止 GPS、BLE 轮询与能耗积分。前台服务还持有局部唤醒锁，适合骑行期间持续记录，但会增加耗电。

Android 13 及以上会额外询问通知权限。定位型前台服务会在应用界面可见时启动，因此不额外索取“始终允许”后台定位权限；持续定位由前台服务及其通知向系统和用户明确声明。拒绝通知权限后系统仍可能在任务管理界面显示前台服务，但建议允许通知，便于确认采集正在运行。部分厂商系统还需要在系统设置中允许自启动、后台运行或关闭针对本应用的电池优化。强行停止应用或关闭蓝牙、定位后无法继续采集。

### TRIP A 与 TOTAL

- `TRIP A` 沿用行程状态机：确认新一程后归零，记录当前单次行程。
- `TOTAL` 只累计 GPS 与 BMS 都新鲜有效时的配对距离和能耗，避免蓝牙失联时只增长里程。
- TOTAL 每约 5 秒及生命周期切换时写入本地偏好；MOCK 数据不会进入 TOTAL。
- “设置 → 能耗面板”可以隐藏整张卡片；“清除 TOTAL”经二次确认后清零总里程、累计放电与回收，不改变当前 TRIP A。
- “设置 → 首页 MOCK 按钮”可隐藏测试入口；隐藏时若 MOCK 正在运行会同时停止模拟数据。

### 有效结果门槛

为避免刚起步时用极小分母产生异常数值：

- 本次平均能效至少需要约 `0.1km` 距离及 `0.01Ah` 净耗电；
- TOTAL 平均能效至少需要约 `0.1km`；
- 60 秒趋势点至少需要约 `0.03km` 及 `0.003Ah`。

预计里程优先使用 TRIP A 能效；本次结果尚未有效时，会回退到更稳定的 TOTAL 平均能效。它是基于历史的动态估算，并非对路况、风阻、温度和驾驶方式的预测。

## BLE 数据链路

- JK 服务 UUID：`FFE0`；读写/通知特征 UUID：`FFE1`。
- 设备信息命令：`0x97`；电芯状态命令：`0x96`。
- 状态帧目标轮询周期为 `500ms`。
- 上一请求未完成时不会重复发送；超过 `1.5s` 后允许超时重试，避免 BLE 分包交叠。
- 已认证后连续约 3 秒没有数据会触发自动重连；从后台返回前台时也会重启轮询、RSSI 与数据看门狗。
- 断开连接后会释放旧 GATT，并在前台或后台采集开启期间自动直连上次成功设备；迟到的旧连接回调不会覆盖新连接状态。
- 状态帧通过 CRC 校验后才会更新界面和积分器。

较高轮询频率可以改善仪表与图表的实时性，但实际刷新速度仍受 BMS 固件、连接间隔、手机蓝牙栈和无线环境影响。

## MOCK 模式

首页浮动按钮可启动 MOCK 行车。模拟数据通过与真实 BMS/GPS 相同的能效入口，包含：

- 急加速与大电流放电；
- 高速巡航；
- 急减速与正电流回收；
- 城区变速；
- 停车与再次起步。

当手机仍连接真实 BMS 时，MOCK 模式不会让两套数据交替写入 UI。真实帧会在后台缓存，退出 MOCK 后恢复显示最新真实数据。

## 图表实现

除首页功率大仪表外，折线与饼图均由本地 ECharts Canvas 渲染：

- ECharts 脚本随 APK 打包，不需要网络加载；
- 一分钟窗口使用固定槽位和稳定数据点 ID，让保留的数据平滑向左移动；
- 更新过程中不强制重复 `resize()`，避免打断 ECharts 过渡动画；
- 通用图表录制上限为 7200 个 BMS 样本，防止列表无限增长。

## 权限与数据

应用可能请求：

- Android 12 及以上的附近设备扫描与连接权限；
- 精确位置权限，用于 GPS 速度以及旧版 Android 的 BLE 扫描要求。
- 后台采集使用的前台服务权限、唤醒锁权限，以及 Android 13 及以上的通知权限。

当前实现只使用定位结果中的速度、精度和时间来积分，不保存轨迹坐标，也不需要账号或云端服务。密码、上次成功连接的设备地址、TOTAL 累计值及显示设置保存在应用本地偏好中。

## 构建

建议使用 Android Studio 自带 JBR/JDK 和仓库中的 Gradle Wrapper。

```powershell
# Windows PowerShell
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"
.\gradlew.bat testDebugUnitTest assembleDebug
```

```bash
# macOS / Linux
./gradlew testDebugUnitTest assembleDebug
```

Debug APK 输出位置：

```text
app/build/outputs/apk/debug/app-debug.apk
```

仓库中的正式签名版本位于：

```text
app/release/app-release.apk
```

建议普通用户优先从 [GitHub Releases](https://github.com/mazemingw/JKBMS-Android/releases) 下载正式签名 APK；同一签名下的后续版本可以直接覆盖升级。

连接手机后可覆盖安装：

```powershell
adb install -r -t app\build\outputs\apk\debug\app-debug.apk
```

## 测试

`EnergyTrackerTest` 覆盖以下核心口径：

- 恒定速度与电流下的 Ah、距离和 `km/Ah` 积分；
- 15 秒停车及恢复行驶；
- 正电流动能回收降低净耗电；
- 500ms 趋势采样与一分钟保留窗口；
- GPS 归零后立即冻结本次、累计与折线；
- 恢复行驶时不跨停车时段补算电流。
- GPS 长时间中断后以两个连续新鲜定位点重新建立积分基线；
- 无定位期间进入临停状态且不增加能耗。

运行单元测试：

```powershell
.\gradlew.bat testDebugUnitTest
```

## 已知限制

- 当前解析逻辑针对本项目已测试的 JK BMS 300 字节状态帧；其他协议版本需要额外适配。
- GPS 在室内、隧道或高楼环境可能不稳定，定位失效期间不会计算能效。
- TRIP A 保存在当前应用进程内，尚未持久化为可查询的历史行程数据库；TOTAL 仅保存汇总值。
- Debug APK 使用调试签名；正式分发前应配置独立签名和发布构建。
